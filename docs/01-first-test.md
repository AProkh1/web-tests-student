# Практика по автоматизации UI

## Цель

Написать свой первый UI-тест на JavaScript и Playwright: найти элементы страницы, выполнить действия и проверить результат.

Продолжительность занятия — 90 минут. Обязательный результат — один тест пустой формы входа. Page Object, авторизацию, fixtures и сетевые моки в этой практике реализовывать не требуется.

## Подготовка

Сделайте форк по [инструкции в README](../README.md#подготовка), склонируйте его и установите зависимости и Chromium. Откройте tests/empty-login.spec.js. Для сценария достаточно гостевого браузера.

## Задание

1. Откройте https://testboard.avito.com/ и форму входа вручную.
2. В DevTools найдите элементы открытия и отправки формы, а также области ошибок email и пароля. Проверьте, что локаторы однозначно находят нужный элемент. Можно использовать CSS и атрибуты data-marker.
3. Заполните пять TODO в tests/empty-login.spec.js. Выполните переход на главную, откройте форму и отправьте её пустой.
4. С помощью expect проверьте два точных текста: «Email обязателен» и «Пароль обязателен».
5. Удалите throw. Запустите тест, затем намеренно измените одно ожидаемое сообщение. Найдите причину падения в логе и отчёте, после чего восстановите правильное ожидание.
6. Сохраните решение в коммите своего форка и передайте преподавателю ссылку и SHA.

Команды:

```bash
npm test -- tests/empty-login.spec.js --headed
npm test -- tests/empty-login.spec.js --debug
npm test -- tests/empty-login.spec.js --repeat-each=3
npm run report
```

## Критерии готовности

- В файле один test() и две содержательные проверки результата через expect.
- Локаторы соответствуют элементам Testboard и не зависят от случайного положения элемента на странице.
- Асинхронные действия выполняются с await. Фиксированные задержки не используются для ожидания элементов.
- Тест проходит три раза подряд; вы можете объяснить причину намеренного падения.
- В коммите есть ваше решение, нет отчётов и секретов.

Сохраните этот тест: на [следующей практике](02-architecture.md) вы перенесёте его на Page Object.
